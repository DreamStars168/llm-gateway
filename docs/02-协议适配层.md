# 02 协议适配层设计

> 目标：4 个入口协议 × 4 个出口协议 的文本链路可用；不支持的字段显式标注而非静默丢弃。
> 核心思想：**能透传就透传，必须翻译才翻译**；翻译统一走内部规范模型（IR）。

---

## 1. 四种协议速览

| 协议 | 入口路径 | 鉴权头 | 流式标识 | 流式载体 | 结束标志 |
|---|---|---|---|---|---|
| OpenAI Chat Completions | `POST /v1/chat/completions` | `Authorization: Bearer` | `"stream": true` | `data: {chunk}` | `data: [DONE]` |
| OpenAI Responses | `POST /v1/responses` | `Authorization: Bearer` | `"stream": true` | `event: x\ndata: {evt}` | `event: response.completed` |
| Anthropic Messages | `POST /v1/messages` | `x-api-key` 或 `Bearer` | `"stream": true` | `event: x\ndata: {evt}` | `event: message_stop` |
| Gemini generateContent | `POST /v1beta/models/{model}:generateContent` | `x-goog-api-key` 或 `?key=` | `:streamGenerateContent?alt=sse` | `data: {candidate}` | 连接关闭（无 DONE） |

> 兼容入口别名：`/messages`、`/chat/completions`、`/responses`、`/v1beta/models/{model}:streamGenerateContent`，供不同客户端硬编码路径使用（sub2api、cc-router 均做了这类兼容）。

## 2. 内部规范模型（IR）

```java
// protocol/canonical/CanonicalRequest.java
public record CanonicalRequest(
    String requestId,
    String tenantId,
    String apiKeyId,
    Protocol ingressProtocol,      // OPENAI_CHAT / OPENAI_RESPONSES / ANTHROPIC / GEMINI
    String requestedModel,         // 客户端传来的原始值
    String virtualModel,           // 归一化后的虚拟模型（如 gpt-4o-mini）
    List<Message> messages,
    String system,                 // 独立 system（Anthropic / Gemini 有独立字段）
    List<ToolDef> tools,
    ToolChoice toolChoice,
    GenerationParams params,       // temperature/topP/topK/maxTokens/stop/seed/presencePenalty...
    ResponseFormat responseFormat, // text / json_object / json_schema
    ReasoningConfig reasoning,     // effort / budgetTokens / include
    List<String> stopSequences,
    boolean stream,
    Map<String, Object> passthrough, // 无法归一化的原始字段，透传时回填
    Map<String, String> headers      // 白名单头（anthropic-beta 等）
) {}

public record Message(Role role, List<ContentPart> parts) {}

public sealed interface ContentPart permits TextPart, ImagePart, ToolUsePart, ToolResultPart, ThinkingPart, DocumentPart {}

public record TextPart(String text, CacheControl cacheControl) implements ContentPart {}
public record ImagePart(String mediaType, String base64OrUrl, boolean isUrl) implements ContentPart {}
public record ToolUsePart(String id, String name, JsonNode input) implements ContentPart {}
public record ToolResultPart(String toolUseId, List<ContentPart> content, boolean isError) implements ContentPart {}
public record ThinkingPart(String text, String signature) implements ContentPart {}
public record DocumentPart(String mediaType, String data, String title) implements ContentPart {}
```

```java
// protocol/canonical/CanonicalChunk.java —— 统一的流式事件
public sealed interface CanonicalChunk
    permits Start, TextDelta, ThinkingDelta, ToolCallStart, ToolCallDelta, ToolCallEnd,
            UsageChunk, Finish, ErrorChunk {

    record Start(String responseId, String model, long createdAt) implements CanonicalChunk {}
    record TextDelta(String text) implements CanonicalChunk {}
    record ThinkingDelta(String text, String signature) implements CanonicalChunk {}
    record ToolCallStart(String id, String name, int index) implements CanonicalChunk {}
    record ToolCallDelta(int index, String partialJson) implements CanonicalChunk {}
    record ToolCallEnd(int index) implements CanonicalChunk {}
    record UsageChunk(int inputTokens, int outputTokens, int cachedTokens, int reasoningTokens) implements CanonicalChunk {}
    record Finish(String stopReason) implements CanonicalChunk {}   // stop / length / tool_calls / content_filter
    record ErrorChunk(String type, String message) implements CanonicalChunk {}
}
```

## 3. 适配器 SPI

```java
public interface IngressAdapter<P> {
    Protocol protocol();
    boolean supports(HttpRequest req, String path);
    CanonicalRequest parse(P payload, GatewayContext ctx);        // 校验 + 归一化
    void writeResponse(ServerHttpResponse resp, Flux<CanonicalChunk> chunks); // 编码回客户端
    void writeError(ServerHttpResponse resp, GatewayException ex);
}

public interface EgressAdapter {
    Protocol protocol();
    UpstreamRequest build(CanonicalRequest req, Channel ch, RouteTarget target); // 生成 URL/Headers/Body
    Flux<CanonicalChunk> decode(UpstreamResponse resp);                         // SSE 解码
    CanonicalChunk decodeNonStream(byte[] body);                                // 非流式
}
```

- 注册：`AdapterRegistry` 在启动时收集所有 `IngressAdapter` / `EgressAdapter` Bean，构建不可变 Map。
- 入口选择：按 `path` 精确匹配 + 方法校验，命中不到返回 `404 not_found`（OpenAI 风格错误体）。
- 出口选择：`channel.protocol()` 决定，同一渠道只允许一种出口协议（与 cc-router 的"接入点协议固定"一致）。

## 4. 快车道：原生透传

### 4.1 判定条件

同时满足才走快车道：
1. `ingress.protocol == channel.protocol`
2. 渠道配置 `passthrough=true`（默认 true）
3. 请求未命中需要网关改写的功能（如强制注入 `stream_options.include_usage`，可通过渠道开关关闭）

### 4.2 实现

```java
// relay/PassthroughRelay.java
public Mono<Void> relay(CanonicalRequest req, Channel ch, ServerHttpResponse out) {
    UpstreamRequest up = passthroughBuilder.build(req, ch);   // 仅重写 model / 替换鉴权头
    return upstreamClient.exchange(up)
        .flatMap(resp -> {
            copySafeHeaders(resp, out);                        // content-type / request-id / 限流头
            out.setStatusCode(resp.status());
            return out.writeWith(
                resp.bodyToFlux(DataBuffer.class)
                    .doOnNext(buf -> meter.accept(buf.readableByteCount()))
                    .doOnComplete(() -> meter.finish())
            );
        });
}
```

**改写范围白名单**（其余字节不动）：
- `model` 字段 → 渠道的真实模型名
- 鉴权头 → 渠道凭证
- 删除客户端带来的 `host`、`content-length`（由客户端库重算）
- 可选注入：`stream_options.include_usage = true`（OpenAI 系，保证拿到 usage）
- 可选注入：`metadata.user_id = tenantId`（便于上游审计）
- 可选转发白名单头：`anthropic-beta`、`anthropic-version`、`openai-beta`、`x-request-id`

> 实现技巧：不大改 JSON。用 Jackson `JsonParser` 定位 `model` 字段的字节区间，做 **字节级替换**（等长填充或重建头部片段），避免全量反序列化 32MB 请求体。若 `model` 长度变化，退化为流式重建（仅一次拷贝，可接受）。

### 4.3 流结束后的 usage 提取

透传模式下网关不解析每个 chunk，只在**尾部**做一次轻量扫描：
- OpenAI：找最后一个含 `"usage":{...}` 的 data 帧
- Anthropic：`message_start` 拿 `input_tokens`，`message_delta` 拿 `output_tokens`
- Gemini：`usageMetadata` 每个 chunk 都带，取最后一个

实现为 `TailUsageSniffer`：环形缓冲保留最后 8KB，流结束后正则/流式解析。零额外内存压力。

## 5. 慢车道：跨协议翻译

### 5.1 转换矩阵

| 入口 \ 出口 | OpenAI Chat | OpenAI Responses | Anthropic | Gemini |
|---|---|---|---|---|
| **OpenAI Chat** | 透传 | 支持（P1） | 支持 | 支持 |
| **OpenAI Responses** | 支持 | 透传 | 支持（P0，Codex→Claude） | 支持（P2） |
| **Anthropic** | 支持（P0，Claude Code→任意） | 支持（P2） | 透传 | 支持（P1） |
| **Gemini** | 支持（P1） | 不支持 | 支持（P2） | 透传 |

> 优先级说明：P0 = 首版必须；P1 = 第二迭代；P2 = 可选。
> 依据：Claude Code 占开发者流量最大，且多数国产模型提供 Anthropic 兼容端点 → 优先"Anthropic 入口 × 各出口"；Codex 走 Responses 入口 → 优先"Responses 入口 × Anthropic 出口"。

### 5.2 字段映射表：Anthropic Messages ⇄ OpenAI Chat

| 概念 | Anthropic | OpenAI Chat | 转换规则 |
|---|---|---|---|
| 系统提示 | 顶层 `system`（string 或 blocks） | `messages[0].role=system` | system blocks 合并为单条；`cache_control` 丢弃并标记 |
| 用户消息 | `role=user`，content blocks | `role=user`，content string/array | 文本块拼接；图片块转 `image_url` |
| 助手消息 | `role=assistant`，含 `tool_use` | `role=assistant` + `tool_calls` | 一一对应 |
| 工具结果 | `role=user` 内 `tool_result` 块 | `role=tool` + `tool_call_id` | 拆成独立 tool 消息，顺序保持 |
| 工具定义 | `tools[].input_schema` | `tools[].function.parameters` | 直接搬运 schema |
| 工具选择 | `tool_choice: {type:any/tool/auto}` | `"required"/{"type":"function"}/"auto"` | `any`→`required` |
| 最大输出 | `max_tokens`（必填） | `max_completion_tokens`（新）/`max_tokens` | 缺省填 4096，并保证 > thinking budget |
| 温度 | `temperature` 0~1 | `temperature` 0~2 | 直传（部分上游会截断） |
| 思考 | `thinking: {type:enabled, budget_tokens}` | `reasoning_effort`（OpenAI）/ `reasoning_content`（DeepSeek） | budget→effort 档位映射；反向 effort→budget |
| 停止词 | `stop_sequences` | `stop` | 直传 |
| 缓存 | `cache_control` | 无 | 丢弃（记录 `dropped_fields`） |
| 结束原因 | `end_turn/max_tokens/tool_use/stop_sequence` | `stop/length/tool_calls/content_filter` | 双向映射表 |

### 5.3 字段映射表：Anthropic Messages ⇄ Gemini generateContent

| 概念 | Anthropic | Gemini | 规则 |
|---|---|---|---|
| 角色 | `user` / `assistant` | `user` / `model` | assistant→model |
| 系统 | `system` | `systemInstruction.parts` | 直搬 |
| 文本 | `text` block | `parts[].text` | 直搬 |
| 图片 | `image` block(base64) | `inlineData{mimeType,data}` | 直搬 |
| 工具 | `tools[].input_schema` | `tools[].functionDeclarations[]` | 包一层 |
| 工具调用 | `tool_use` | `functionCall{name,args}` | id 由网关生成（Gemini 无 id） |
| 工具结果 | `tool_result` | `functionResponse{name,response}` | 需按 name 反查 |
| 思考 | `thinking` | `thought: true` + `thoughtSignature` | 必须回传 signature，否则多轮工具调用失败 |
| 最大输出 | `max_tokens` | `generationConfig.maxOutputTokens` | 直传 |
| 停止 | `stop_sequences` | `generationConfig.stopSequences` | 直传 |
| 结束原因 | `end_turn/max_tokens/tool_use` | `STOP/MAX_TOKENS/SAFETY` | 映射 |

> Gemini 的 `thoughtSignature` 是**必须原样回传**的字段，否则工具调用多轮会 400。IR 中用 `ThinkingPart.signature` 承载，跨协议时若目标协议不支持则丢弃但记录告警。

### 5.4 SSE 事件映射（Anthropic → OpenAI Chat）

| Anthropic 事件 | 处理 |
|---|---|
| `message_start` | 发 `Start` + 首个 `role:assistant` chunk；记录 `input_tokens` |
| `content_block_start` (text) | 无输出 |
| `content_block_start` (tool_use) | `ToolCallStart(id, name, index)` → `delta.tool_calls[{index,id,type:function,function:{name,arguments:""}}]` |
| `content_block_delta` (`text_delta`) | `delta.content` |
| `content_block_delta` (`input_json_delta`) | `delta.tool_calls[{index,function:{arguments:partial}}]` |
| `content_block_delta` (`thinking_delta`) | `delta.reasoning_content`（DeepSeek 风格，客户端可折叠） |
| `content_block_stop` | 无输出（或 `ToolCallEnd`） |
| `message_delta` | 记录 `output_tokens`、`stop_reason` |
| `message_stop` | 发 `finish_reason` + usage 帧 + `data: [DONE]` |
| `ping` | 丢弃（或转发为注释行保活） |
| `error` | `ErrorChunk` → OpenAI 错误体 + `[DONE]` |

**编码规范**（易踩坑，逐条写成测试）：
1. 每个事件必须是 `data: {json}\n\n`，JSON 中不能有裸换行。
2. 首帧必须带 `role`，否则部分客户端不渲染。
3. `finish_reason` 只出现在倒数第二帧（usage 帧为最后一帧）。
4. 客户端断开时取消上游订阅（`doFinally(signal -> upstream.dispose())`），否则上游继续计费。
5. 心跳：上游 15s 无数据时，网关发 `: keep-alive\n\n` 注释行，防止中间层超时断连（Nginx/ALB 默认 60s）。
6. 必须 flush：WebFlux 默认按 buffer 聚合，需 `response.writeAndFlushWith` 或对每帧 `DataBuffer` 单独写出。

## 6. 非流式请求

- 上游非流式响应体可能很大（含 base64 图片），用 `DataBuffer` 直接回写，**不反序列化**（同协议时）。
- 跨协议时必须反序列化，限制 `maxInMemorySize=64MB`，超出返回 `413`。
- 统一在响应头注入：`x-gateway-request-id`、`x-gateway-channel`、`x-gateway-model`、`x-gateway-latency-ms`（便于排查，敏感渠道名可脱敏为 hash）。

## 7. 错误体规范

对外统一为 OpenAI 风格（Anthropic 入口则输出 Anthropic 风格），便于客户端 SDK 直接识别：

```json
{
  "error": {
    "message": "Upstream channel 'openai-main' returned 429: rate limit exceeded",
    "type": "rate_limit_error",
    "code": "upstream_rate_limited",
    "param": null,
    "request_id": "req_01HX..."
  }
}
```

| 网关错误码 | HTTP | 语义 | 是否重试下一渠道 |
|---|---|---|---|
| `invalid_api_key` | 401 | Key 不存在/禁用/过期 | 否 |
| `insufficient_quota` | 402 | 余额或额度不足 | 否 |
| `model_not_found` | 404 | 虚拟模型未配置或无可用渠道 | 否 |
| `invalid_request` | 400 | 报文校验失败 | 否 |
| `context_length_exceeded` | 400 | 超模型上下文 | 否（可换更长上下文渠道） |
| `upstream_rate_limited` | 429 | 上游限流 | 是 |
| `upstream_unavailable` | 503 | 连接失败/5xx/熔断打开 | 是 |
| `upstream_timeout` | 504 | 首字节超时 | 是（仅未写出时） |
| `gateway_overloaded` | 429 | 本地并发闸门满 | 否 |
| `content_filtered` | 400 | 上游安全拦截 | 否 |

## 8. 协议一致性测试（必须做，面试可讲）

采用 **夹具驱动**（fixture-driven）测试：

```
src/test/resources/fixtures/
├── anthropic/
│   ├── stream_text.sse          # 真实录制
│   ├── stream_tool_use.sse
│   ├── stream_thinking.sse
│   └── nonstream_error.json
├── openai/
│   ├── stream_text.sse
│   ├── stream_tool_calls.sse
│   └── stream_reasoning.sse
└── gemini/
    ├── stream_text.sse
    └── stream_function_call.sse
```

断言策略：
1. **解码断言**：`fixture → List<CanonicalChunk>` 与 golden JSON 比对（AssertJ `isEqualTo`）。
2. **编码断言**：`List<CanonicalChunk> → SSE 文本`，逐帧比对（忽略 `id`、`created` 等时间字段）。
3. **往返断言**：A→IR→B→IR' ，检查关键语义（文本、工具名、参数、停止原因）不变。
4. **混沌断言**：随机插入空行、CRLF、超长单行、被截断的帧，解析器不得抛未捕获异常。

覆盖率目标：`protocol/` 包行覆盖 ≥ 85%，四个入口的 `parse` 与四个出口的 `build` 必须有参数化用例。

## 9. 已知不支持项（文档化，避免用户踩坑）

| 场景 | 表现 | 建议 |
|---|---|---|
| Anthropic `cache_control` → OpenAI/Gemini | 丢弃，不报错 | 想用缓存请走 Anthropic 原生渠道 |
| OpenAI `logprobs` → 其他协议 | 丢弃 | — |
| OpenAI `n>1` → Anthropic/Gemini | 仅返回第 1 条 | — |
| Gemini `safetySettings` → 其他 | 丢弃 | — |
| OpenAI `response_format: json_schema` → Gemini | 转 `responseMimeType` + `responseSchema`（尽力） | 复杂 schema 可能降级 |
| 图片 URL（非 base64）→ Gemini | 需网关下载后转 base64 | 限制 20MB，防 SSRF |
| Anthropic `thinking.signature` → OpenAI | 丢弃 | 多轮思考上下文会弱化 |
