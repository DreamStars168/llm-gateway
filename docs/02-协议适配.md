# 协议适配

> 支持 OpenAI Chat Completions / Anthropic Messages / Gemini generateContent 三类协议，
> 覆盖入口解析与出口构造，SSE 全链路流式。

---

## 1. 核心思路：IR + 双车道

不写 4×4 = 16 个转换器，而是定义中间表示（Internal Representation）：

```
入口协议 ──parse──▶ CanonicalRequest ──build──▶ 出口协议
                          │
                          └─ 路由与计费只认 IR，与协议无关
```

- **快车道**：入口协议 == 出口协议 → 字节级透传，IR 都不需要
- **慢车道**：跨协议 → 走 IR 翻译

新增一种协议只需写「解析器 + 构造器 + 流解码器」三个类，不用改路由和计费。

## 2. IR 模型

```java
record CanonicalRequest(
    String requestedModel,     // 客户端原始模型名（用于回显）
    String virtualModel,       // 归一化后的路由键
    String system,             // 独立 system（Anthropic/Gemini 有独立字段）
    List<Message> messages,
    List<ToolDef> tools,
    ToolChoice toolChoice,
    GenerationParams params,   // temperature/topP/topK/maxTokens/stop/seed
    ReasoningConfig reasoning, // effort / budgetTokens
    boolean stream,
    Map<String,Object> passthrough,  // 无法归一化的原始字段
    List<String> droppedFields       // 转换中丢弃的字段（用于告警）
)

sealed interface ContentPart
    permits TextPart, ImagePart, ToolUsePart, ToolResultPart, ThinkingPart, DocumentPart
```

`ContentPart` 用 **sealed interface**，让转换器在 `switch` 时获得编译期穷尽检查——
新增一种片段类型，所有转换器都会编译失败，不会漏改。

## 3. 流式事件模型

```java
sealed interface CanonicalChunk
    permits Start, TextDelta, ThinkingDelta,
            ToolCallStart, ToolCallDelta, ToolCallEnd,
            UsageChunk, Finish, ErrorChunk
```

跨协议转换变成「解码 → 事件流 → 编码」两段：

```
上游 SSE ──Decoder──▶ Flux<CanonicalChunk> ──Encoder──▶ 客户端 SSE
```

每个方向只需理解自己那一侧的协议，不需要 N×N 组合。

## 4. 三协议差异矩阵

| 维度 | OpenAI Chat | Anthropic | Gemini |
|---|---|---|---|
| 角色 | `system/user/assistant/tool` | `user/assistant` + 顶层 system | **只有 `user`/`model`** |
| 系统提示 | messages 首条 | 顶层 `system` | 顶层 `systemInstruction` |
| 工具结果 | 独立 `role=tool` 消息 | user 消息内 `tool_result` block | user 消息的 `functionResponse` part |
| 工具调用 ID | 有 `id` | 有 `id`（`toolu_xxx`） | **无 id，靠 name 关联** |
| 参数位置 | 顶层 | 顶层 | **`generationConfig` 内** |
| Schema 类型 | 小写 `object/string` | 小写 | **大写 `OBJECT/STRING`** |
| 流结束标志 | `[DONE]` | `message_stop` | **无标记，靠连接关闭** |
| usage 位置 | 末尾单独帧 | `message_start` + `message_delta` | 每帧 `usageMetadata`（累计） |
| 思考 | `reasoning_content` | `thinking` block | `thought: true` + `thoughtSignature` |

### 4.1 Anthropic ⇄ OpenAI 字段映射

| 概念 | Anthropic | OpenAI Chat | 规则 |
|---|---|---|---|
| 系统提示 | 顶层 `system`（string 或 blocks） | `messages[0].role=system` | blocks 合并为单条；`cache_control` 丢弃 |
| 工具定义 | `tools[].input_schema` | `tools[].function.parameters` | 直接搬运 schema |
| 工具选择 | `{type:any/tool/auto}` | `"required"/{"type":"function"}/"auto"` | `any` → `required` |
| 最大输出 | `max_tokens`（必填） | `max_completion_tokens` | 缺省填 4096，且需 > thinking budget |
| 思考 | `thinking.budget_tokens` | `reasoning_effort` | budget → effort 档位映射 |
| 结束原因 | `end_turn/max_tokens/tool_use` | `stop/length/tool_calls` | 双向映射表 |

### 4.2 Anthropic ⇄ Gemini 关键差异

**角色**：Gemini 只有 `user` / `model`，没有 system 与 tool 角色。

```java
// Message.Role.geminiWire()
ASSISTANT → "model"
其他（SYSTEM/USER/TOOL） → "user"
```

**Schema 类型必须大写**，这是最容易踩的坑：

```java
private JsonNode sanitizeSchema(JsonNode schema) {
    copy.put("type", type.toUpperCase());   // object → OBJECT
    // 递归处理 properties / items
}
```

**工具调用无 ID**：Gemini 只给 `functionCall.name` + `args`。
流入侧合成稳定 id：`call_{name}_{index}`；流出侧丢弃 id。

**流式无 `[DONE]`**：连接关闭即结束，网关必须补发收尾事件，否则客户端一直等：

```java
.concatWith(Flux.defer(() -> {
    if (finished[0]) return Flux.empty();
    String closing = encoder.encode(new CanonicalChunk.Finish("end_turn"));
    return closing.isEmpty() ? Flux.empty() : Flux.just(closing);
}))
```

**usage 是累计值**：每帧都带 `usageMetadata`，用 `Math.max` 而非 `+=`，避免重复累加。

## 5. SSE 处理要点

### 5.1 帧解析必须自己缓冲

网络分片可能把一帧切在任意位置。SSE 规约：事件以空行分隔，同一事件可有多行 `data:`。

```java
// 正确：按 \n 切行，空行代表事件边界
while ((nl = buffer.indexOf("\n")) >= 0) {
    String line = buffer.substring(0, nl);
    if (line.endsWith("\r")) line = line.substring(0, line.length()-1);
    buffer.delete(0, nl + 1);
    if (line.isEmpty()) { /* 事件结束 */ }
    else if (line.startsWith("data:")) currentData.add(...);
}
```

### 5.2 六条编码红线

1. 每个事件必须是 `data: {json}\n\n`，JSON 中不能有裸换行
2. 首帧必须带 `role`，否则部分客户端不渲染
3. `finish_reason` 只出现在倒数第二帧（usage 帧为最后一帧）
4. 客户端断开时**必须取消上游订阅**，否则上游继续计费
5. 上游 15s 无数据时发注释行心跳，防止中间层超时断连
6. 必须 flush：WebFlux 默认按 buffer 聚合，需逐帧 `DataBuffer` 写出

### 5.3 Anthropic 事件顺序（严格约定）

```
message_start
  content_block_start(idx=0)
    content_block_delta × N
  content_block_stop(idx=0)
  content_block_start(idx=1)   ← 工具调用是新 block
    content_block_delta × N
  content_block_stop(idx=1)
message_delta(usage, stop_reason)
message_stop
```

顺序错了客户端会解析失败。`AnthropicSseEncoder` 内部维护当前打开的 block 索引与类型。

## 6. 已知不支持项

| 场景 | 表现 | 建议 |
|---|---|---|
| `cache_control` → OpenAI/Gemini | 丢弃，不报错 | 想用缓存请走 Anthropic 原生渠道 |
| OpenAI `logprobs` → 其他 | 丢弃 | — |
| OpenAI `n>1` → Anthropic/Gemini | 仅返回第 1 条 | — |
| Gemini `safetySettings` → 其他 | 丢弃 | — |
| 同轮同名工具多次调用 | Gemini 无 id，反查歧义 | 需在 IR 维护 name→id 映射表 |
| 图片 URL → Gemini | 只支持 `fileData`（需公开可访问） | 网关下载后转 base64 |
| `thoughtSignature` 多轮回传 | 未做跨轮持久化 | 需在会话状态里保存签名 |
| Schema `$ref`/`oneOf` | 未处理 | Gemini 本身支持有限 |

## 7. 协议一致性测试

采用夹具驱动（fixture-driven）测试：

```
src/test/resources/fixtures/
├── anthropic/  stream_text.sse / stream_tool_use.sse / stream_thinking.sse
├── openai/     stream_text.sse / stream_tool_calls.sse
└── gemini/     stream_text.sse / stream_function_call.sse
```

断言策略：
1. **解码断言**：`fixture → List<CanonicalChunk>` 与 golden JSON 比对
2. **编码断言**：`List<CanonicalChunk> → SSE 文本`，逐帧比对（忽略时间字段）
3. **往返断言**：A→IR→B→IR'，关键语义（文本、工具名、参数、停止原因）不变
4. **混沌断言**：随机插入空行、CRLF、超长单行、截断帧，解析器不得抛未捕获异常

当前共 41 个协议相关测试，覆盖三种协议的请求构造、流式解码、非流式转换。

## 8. 实现结构

```
protocol/
├── canonical/          # IR 定义（零 Spring 依赖）
│   ├── CanonicalRequest / CanonicalChunk
│   ├── ContentPart / Message / ToolDef
│   └── GenerationParams / ReasoningConfig
├── anthropic/          # Messages 协议
│   ├── AnthropicParser          # 请求 → IR
│   ├── AnthropicSseEncoder      # CanonicalChunk → SSE
│   └── OpenAiToAnthropicNonStream
├── openai/             # Chat Completions
│   ├── OpenAiChatRequestBuilder # IR → 请求
│   └── OpenAiChatStreamDecoder  # SSE → CanonicalChunk
├── gemini/             # generateContent
│   ├── GeminiRequestBuilder
│   ├── GeminiStreamDecoder
│   └── GeminiToAnthropicNonStream
└── sse/
    ├── SseFrameParser          # 帧重组
    └── SseBridge               # 解码 → 编码的桥接
```

**有状态类必须每请求一个实例**（如 `OpenAiChatStreamDecoder` 记录 lastId、
`AnthropicSseEncoder` 记录 block index），不能作为单例 Bean 共享，否则并发串数据。
